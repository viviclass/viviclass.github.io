# GPT × Skill｜把每天重複做的事，變成自己的 AI 技能

> 薇光AI課堂（ViVi 老師）的課後操作教學。完全沒做過 Skill 的人，跟著「想、找、拆、包、裝、測、改」七步，就能做出自己的第一個 Skill。
> 互動版網頁：https://viviclass.github.io/gpt-skill/　｜　最後更新：2026-10-05　｜　作者：ViVi 老師（薇光AI課堂）

**Skill 是什麼？** 可以先理解成一份 AI 看得懂的工作 SOP。把你做事的方法寫清楚，之後每次開新對話交給 AI，它就照你的方法做，不用每次重新解釋。

## 流程總覽

| 大階段 | 對應步驟 |
| --- | --- |
| 找出重複事 | STEP 1 想事情、STEP 2 找對話 |
| 製作 Skill | STEP 3 拆流程、STEP 4 包 Skill、STEP 5 裝 Skill |
| 測試應用 | STEP 6 測 Skill |
| 效率升級 | STEP 7 改 Skill |

## 什麼事情適合做成 Skill？

符合越多越適合：一週至少會做 2～3 次；每次處理流程差不多；每次都需要重新跟 AI 解釋；最後通常有固定的輸出成果。
例如：開會紀錄、社群文案、圖片提示詞、商品介紹、短影音腳本、客戶需求整理、活動企劃、課程通知。

## STEP 1｜想事情

想一件你平常經常處理、每次流程都差不多的工作，例如「開會紀錄」。越常做、越重複，越值得先做成 Skill。

## STEP 2｜找對話

回到 ChatGPT，找出一次你覺得「這一次 GPT 真的做得很好」的完整對話。不要只看最後答案，要看整個過程：你怎麼問、GPT 怎麼答、你怎麼修改、GPT 怎麼調整、最後怎麼得到滿意的結果。
最有價值的不一定是最後一個 Prompt，而是你和 GPT 來回合作後形成的整套成功流程。

## STEP 3｜拆流程

在那個成功對話最下面，貼上這段指令：

```text
請分析我們上面這整段對話，不要只摘要內容。

我要把這次成功的合作流程做成一個可以重複使用的 Skill。

請幫我抽出：

1. 這個 Skill 的目的
2. 什麼情況下會使用
3. 我需要提供哪些資料
4. AI 應該按照什麼順序處理
5. 過程中有哪些判斷規則
6. 哪些細節一定要確認，不能自行猜測
7. 固定的輸出格式
8. 哪些事情不能做
9. 最後應該怎麼檢查成果

請先給我「Skill 規格總覽」。

暫時不要直接打包成檔案。
```

GPT 回覆「Skill 規格總覽」後，先人工確認：這真的是我平常做事的方法嗎？執行順序正確嗎？有沒有漏掉重要步驟？AI 有沒有自己增加我沒要求的內容？哪些事情一定要問我、不能自己猜？
先確認流程，再打包 Skill。

## STEP 4｜包 Skill

規格確認沒問題後，貼上這段指令請 GPT 正式打包：

```text
這個 Skill 流程確認沒問題。

請依照剛剛確認的 Skill 規格，幫我整理成一個可以重複使用的完整 Skill。

這個 Skill 的名稱固定為：「【Skill 名稱】」。
請直接使用這個名稱，不要自己改名、翻譯或加字。

請確保內容包含：

1. Skill 名稱
2. Skill 用途
3. 適用情境
4. 使用者需要提供的資料
5. 固定執行流程
6. 判斷規則
7. 哪些資訊缺少時一定要先詢問
8. 固定輸出格式
9. 禁止事項
10. 最終檢查方式

請不要省略前面已經確認的重要規則。
```

先幫 Skill 取一個看名字就知道用途的中文名稱，例如：開會紀錄、文案製作、圖片提示詞、短影音分鏡、活動企劃。**這個名稱要寫進下面的指令，讓 ChatGPT 照用、不要自己改名**（互動版網頁會自動把你取的名稱填進指令；這裡請自行把指令裡的【Skill 名稱】換成你的名稱）。

接著輸出成 `.md` 檔（MD 可以先理解成一份 AI 看得懂的工作 SOP）：

```text
請把這個 Skill 整理成完整的 Markdown 格式，並輸出成 .md 檔。

Skill 名稱固定為：「【Skill 名稱】」，請不要更改。

請完整保留：

- Skill 名稱
- 用途
- 適用情境
- 使用者輸入
- 執行流程
- 判斷規則
- 必須確認的資訊
- 輸出格式
- 禁止事項
- 最終檢查清單

請確保即使換到全新的 AI 對話，另一個 AI 只讀這份內容，也能理解並按照這個流程執行。
```

輸出之後，先請 GPT 自查名稱有沒有被改掉：

```text
請列出這份 .md 檔裡的 Skill 名稱，並確認是否和我指定的「【Skill 名稱】」完全相同。

如果不同，請改成「【Skill 名稱】」，並重新輸出完整 .md 檔，其他內容不要動。
```

MD 是可攜式的 Skill / SOP 文件，不代表每個 AI 平台都會自動安裝。不同平台可能需要上傳 MD、貼入 Instructions，或放到 Project / Knowledge / Skill 等對應位置。

## STEP 5｜裝 Skill

做好 Skill 還不夠，裝進去之後，才可以在新的對話裡重複使用。

**安裝方法（上傳 MD ＋ 貼安裝指令）：** 開一個新的 ChatGPT 對話 → 按迴紋針，上傳 STEP 4 輸出的 `.md` 檔 → 貼上下面的安裝指令送出 → 等 ChatGPT 回覆「已安裝」，並告訴你名稱、用途和呼叫方式。

```text
我上傳了一份 Skill 的 .md 檔，請把它安裝成可以重複使用的 Skill。

安裝時請注意：
1. 使用檔案裡的 Skill 名稱
2. 不要改寫或省略檔案裡的任何規則
3. 裝好後告訴我：Skill 名稱、用途，以及我之後要怎麼呼叫它
4. 如果檔案裡的 Skill 名稱和「【Skill 名稱】」不同，請先告訴我，不要自己決定

如果你的環境沒有辦法安裝 Skill，請直接告訴我原因，不要假裝已經安裝，並告訴我最接近的替代做法。
```

看到 ChatGPT 回覆「已安裝」，並出現「查看已安裝的 Skill」，才算安裝完成。請記下它回覆的「呼叫方式」：呼叫用的名稱以它回覆的為準，有時會和你取的中文名稱不一樣。

**另一條路：** 如果你的 ChatGPT 有 Skills 管理頁，也可以從那裡匯入：開啟 Skills 管理位置 → 新增／匯入 Skill → 上傳 `.md` 檔 → 確認名稱 → 完成安裝，再開新對話測試。

**安裝後怎麼用：**
- 方法 1：直接在新對話說需求，ChatGPT 可依任務內容判斷是否使用相關 Skill。
- 方法 2：明確指定，照 ChatGPT 安裝完告訴你的呼叫方式用。常見的是直接說「使用〈Skill 名稱〉，幫我……」，也可以用 `@` 叫出 Skill。例如：`使用「開會紀錄」，幫我整理下面這場會議。`

**@ 和 / 的差別：** `@` 是明確指定這次要用哪一個 Skill；`/` 是叫出目前介面可用的命令／功能選單，部分介面可能顯示已啟用的 Skill，但不要當成 `/技能名稱` 在所有裝置都一定能用。

**如果沒辦法安裝：** 不同帳號、方案、裝置或工作區的介面可能不同。如果 ChatGPT 回覆沒有安裝功能，仍可使用 `.md`：新對話上傳 `.md` 後貼這句：

```text
請依照這份 Skill 執行接下來的任務。
```

不能上傳檔案時，先把 Skill 全文貼進對話，再貼這句：

```text
請閱讀並依照以上 Skill 規則執行後續任務。
```

有安裝：新對話可直接使用／指定 Skill。只有 MD：新對話需要重新上傳或貼入。

**名稱三對照：** 安裝完成後，把三個名字並排看一次：① 我取的名稱、② MD 檔裡的名稱、③ ChatGPT 回報的呼叫名稱。①和②必須一致，不一致就用「核對名稱」指令請 GPT 改回來、重新輸出再安裝；③可能是 ChatGPT 的顯示方式，之後請用它回報的名稱呼叫，並記下來。

## STEP 6｜測 Skill

不要在原本製作 Skill 的聊天室測試，那個 GPT 已經知道前面所有資訊，測試會失真。換一個新對話測。

- **TEST 0 先確認它讀到了：** 開新對話，貼下面這段（把【Skill 名稱】換成你的），先不要給它工作，看 ChatGPT 說得對不對：

```text
請先不要開始做事。

請使用我剛安裝的「【Skill 名稱】」，告訴我：
1. 這個 Skill 的名稱和用途
2. 我需要提供哪些資料
3. 缺少哪些資料時，你一定要先問我
```

- **TEST 1 正常測試：** 用 ChatGPT 安裝完告訴你的呼叫方式叫出 Skill（沒有安裝功能就上傳或貼入 MD），給它一個新的正常案例。檢查：有沒有按流程？有沒有少做步驟？輸出格式對不對？有沒有出現沒要求的內容？最後有沒有完成檢查？
- **TEST 2 故意少給資料：** 例如 Skill 需要活動名稱、日期、地點、對象，這次故意不給日期。AI 自己猜日期＝不及格，Skill 還需要修；AI 告訴你缺少日期、需要確認＝及格。

不是只測它會不會做，還要測它知不知道「什麼時候不能做」。

## STEP 7｜改 Skill

不是改答案，是改規則。測試出錯時，不要只說「幫我改一下」，那樣只修這一次。常見問題分成：輸入問題、流程問題、規則問題、判斷問題（缺資料沒先問）、輸出問題、檢查問題。

貼上這段指令，請 GPT 修改 Skill 本體：

```text
剛剛測試這個 Skill 時，出現以下問題：

【請在這裡貼上問題】

請不要只修改這一次的答案。

請先判斷問題出在 Skill 本體的哪一個部分：

- 輸入條件
- 執行流程
- 判斷規則
- 必須確認的資訊
- 輸出格式
- 禁止事項
- 最終檢查

請幫我修改 Skill 本體。

修改後請告訴我：

1. 原本哪裡有問題
2. 修改了哪一條規則
3. 為什麼這樣修改
4. 未來如何避免再次發生

最後請重新輸出完整最新版 Skill。
```

改完要再開新對話測一次，同一個問題不再出現，才算修改成功。

**Skill 改完，也要更新安裝版本：** 重新輸出最新版 `.md` → 更新／重新匯入 Skill → 確認舊版本是否需要停用 → 再開新對話測試 → 確認目前使用的是最新版。

**版本管理：** 每次重要修改留一個版本，例如 `開會紀錄_v1.md`、`開會紀錄_v2.md`。建議記錄 Skill 名稱、版本、修改日期、修改原因、修改內容。

## 常見問題

**Skill 是什麼？**
Skill 可以先理解成一份 AI 看得懂的工作 SOP。把你做事的方法寫清楚，之後每次開新對話交給 AI，它就照你的方法做，不用每次重新解釋。

**完全沒做過 Skill，可以自己做嗎？**
可以。不用從零寫，找一次你在 ChatGPT 最滿意的成功對話，請 GPT 拆成流程、打包成 Skill 就行。整個流程是想、找、拆、包、裝、測、改七步，每一步都有可直接複製的指令。

**什麼事情適合做成 Skill？**
一週至少會做 2～3 次、每次處理流程差不多、每次都要重新跟 AI 解釋、最後有固定輸出成果的事。例如開會紀錄、社群文案、圖片提示詞、短影音腳本、客戶需求整理。

**我的 ChatGPT 沒有 Skills 功能怎麼辦？**
不同帳號、方案、裝置或工作區的介面可能不同。沒有安裝功能時，仍可新開對話、上傳 .md 檔，並說「請依照這份 Skill 執行接下來的任務」；不能上傳就貼上 Skill 內容。差別是只有 MD 時，每次新對話都要重新上傳或貼入。

**為什麼要開新對話測試 Skill？**
原本做 Skill 的聊天室已經知道前面所有資訊，測試會失真。要用正常案例和故意少給資料的案例各測一次，確認它缺資料時會先問你，而不是自己猜。

**Skill 測出問題要怎麼改？**
要改 Skill 本體的規則，不是只改這一次的答案。改完要重新輸出最新版 .md、更新安裝的版本，再開新對話測一次，同一個問題不再出現才算改成功。
